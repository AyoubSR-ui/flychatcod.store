GOAL OF THIS LAYER
Implement the first usable embeddable widget system for FlyChat COD.

This layer must deliver:
1. Public widget backend endpoints
2. An embeddable widget UI route inside the existing frontend app
3. A real widget.js loader script
4. End-to-end message flow from external website → widget → backend → seller inbox data
5. Honest MVP implementation only, no fake realtime, no fake AI

ARCHITECTURE REQUIREMENT
Use the recommended architecture:
- lightweight loader script
- iframe-based widget UI

The host website should only load a small script.
The full chat UI must render inside an iframe to avoid CSS/JS conflicts with host websites.

Expected embed snippet:
<script>
  window.FLYCHAT_CONFIG = { storeId: "STORE_ID" };
</script>
<script src="http://localhost/widget.js"></script>

For now, use localhost/dev-safe URLs and existing local reverse proxy assumptions.
Do not hardcode production domains.
Structure it so production domains can be swapped in later with config/env variables.

PART A — PUBLIC WIDGET BACKEND
Add public-safe backend routes under /api/widget/public or another clean public namespace.

Required endpoints:

1. GET public widget config by store
Purpose:
- fetch public widget settings for a store
- only return safe public fields

Example:
GET /api/widget/public/config/:storeId

Response should include only safe fields like:
- storeId
- storeName
- widget enabled/disabled
- primary color
- position
- welcome message
- default language
- supported languages if available

Do NOT expose private store settings.

2. POST create or resume widget session
Purpose:
- accept visitor identity from browser localStorage if available
- create a session or return existing info
- support anonymous visitors

Example:
POST /api/widget/public/session

Request body example:
{
  "storeId": "xxx",
  "visitorId": "optional-existing-visitor-id",
  "language": "fr",
  "currentPageUrl": "https://example.com/product/123",
  "referrer": "https://google.com"
}

Response example:
{
  "visitorId": "...",
  "sessionId": "...",
  "storeId": "...",
  "language": "fr"
}

3. POST create conversation for widget visitor
Purpose:
- create a new conversation if none exists
- associate it with store and visitor
- mark channel as widget

Example:
POST /api/widget/public/conversations

Request body example:
{
  "storeId": "xxx",
  "visitorId": "...",
  "language": "fr",
  "currentPageUrl": "https://example.com/product/123",
  "referrer": "https://google.com"
}

Response:
{
  "conversationId": "...",
  "status": "open"
}

4. GET widget conversation messages
Purpose:
- fetch message thread for widget conversation

Example:
GET /api/widget/public/conversations/:conversationId/messages

This endpoint must only expose messages safe for widget users.

5. POST send widget message
Purpose:
- allow visitor to send a message into the conversation

Example:
POST /api/widget/public/conversations/:conversationId/messages

Request body example:
{
  "visitorId": "...",
  "content": "Bonjour, je veux commander",
  "language": "fr"
}

Behavior:
- validate message length and fields with Zod
- create message in DB
- update conversation last activity if schema supports it
- tag sender as customer
- ensure conversation belongs to same store context

- /widget.js

This script must:
- read window.FLYCHAT_CONFIG
- validate that storeId exists
- create a floating launcher button on the host page
- create a hidden iframe container
- point iframe to /embed/widget?storeId=...&lang=...
- toggle iframe open/close

Loader requirements:

If needed, serve widget.js from the API server.
Choose the cleanest practical implementation for this monorepo.
